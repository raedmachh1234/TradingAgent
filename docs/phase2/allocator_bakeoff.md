# Allocator bake-off

Generated by `python -m quantbot bakeoff` (seed 0, 240 months of synthetic monthly returns for five made-up asset classes, Student t(5) shocks; Python 3.11.18). Not market data: these numbers compare software, not investments.

**Decision rule, fixed before the first run.** A library passes when its weights are within 1e-3 of the reference (scipy SLSQP) for minimum variance and within 1e-2 for maximum Sharpe, with no constraint violated (long only, fully invested, at most 40% per asset), and it installs on Python 3.11 and 3.13. Among passing libraries: most of the needed features (walk-forward, purged cross-validation, CVaR, drawdown risk, scikit-learn API), then fewest dependencies, then speed.

**Decision: skfolio.** skfolio passes and has 5 of 5 needed features, 18 dependencies, 14.0 ms per solve.

| Library | Min-variance gap | Max-Sharpe gap | ms per solve | Dependencies | Features | Passes |
| --- | --- | --- | --- | --- | --- | --- |
| skfolio 1.12.9 | 5.5e-06 | 3.1e-05 | 14.0 | 18 | walk_forward, purged_cv, cvar, drawdown, sklearn_api | yes |
| PyPortfolioOpt 1.6.0 | 1.2e-07 | 1.8e-09 | 5.7 | 24 | cvar, drawdown | yes |
| Riskfolio-Lib 7.4.1 | 3.8e-07 | 1.6e-07 | 37.0 | 93 | cvar, drawdown | yes |

Gap = largest difference from the reference weight. Dependencies = installed packages the library pulls in, counted transitively.

## Walk-forward check: minimum variance, rebalanced quarterly on a trailing 5-year window

| Solver | Yearly volatility | Yearly return | Sharpe (rf 2%) |
| --- | --- | --- | --- |
| reference | 5.09% | 1.92% | -0.015 |
| skfolio | 5.09% | 1.92% | -0.015 |
| PyPortfolioOpt | 5.09% | 1.92% | -0.015 |
| Riskfolio-Lib | 5.09% | 1.92% | -0.015 |
| equal weights | 6.92% | 3.20% | 0.174 |

The libraries match each other, as they solve the same problem. Minimum variance lowers risk against equal weights here but also lowers return: it is a risk tool, not a return forecast.

## Installs on both supported Pythons

Checked on 2026-11-11: all three libraries install and import on Python 3.11.18 and 3.13.18, and the full test
suite, including the agreement test in `tests/test_allocators.py`, passes on both (372 tests).

## Licences of what each library pulls in

Read from package metadata on 2026-11-11. skfolio and PyPortfolioOpt bring only permissively licensed packages.
Riskfolio-Lib also brings certifi and tqdm (MPL-2.0, used unmodified) and vectorbt 1.2.0, which is Apache 2.0 with
Commons Clause. The comparison never loads vectorbt (checked after a full run), and Riskfolio-Lib is kept in the
separate `bakeoff` extra, so the normal install (`.[allocators]`, skfolio only) contains no Commons-Clause code.
